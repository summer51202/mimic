# Motion 家族校準（Gate A 最後一個家族）

日期：2026-11-06。狀態：待實作。Gate A 現況：除 Motion 外七個家族已核准。

## 依據

- 校準 brief：一個 1200×800 審閱視窗的獨立 HTML，示範「不頻繁的三格標題瞄眼／眨眼」「2–4 格、4–6 fps 的待機循環」「播放一次的 4–6 格動作」「可跳過的一次性完成序列」「打字機效果且完整句子另外提供給輔助技術」；**同時只能有一個主要角色動畫**。拒絕：持續跟隨游標、超過一個主要角色動畫、延遲操作或導覽、強制探索、搶焦點、重複慶祝、減少動態模式把結果狀態一起移除（應直接顯示結果）。
- 2026-09-14 規格：基礎狀態 2–4 格短循環，動作 4–6 格，慶祝可較豐富但可跳過；不得拖慢導覽、表單或錯誤恢復；標題只在 Landing／Home 偶爾眨眼或瞄一下，hover／tap 反應一次，不持續追蹤指標；對話打字中點擊立即補完，完成後點擊前進。
- 舊樣本 `samples/motion-calibration.html`（2026-09-18）用 CSS 位移模擬舊素材，沒有真正的逐格圖，只作結構參考。

## 2. 節奏與規則（預設值，審閱時可調）

| 動畫 | 觸發 | 節奏 |
|---|---|---|
| 標題眨眼／瞄眼 | 每 8–15 秒隨機一次；hover／tap 反應一次；離開視窗或分頁隱藏時暫停 | 3 格，每格約 90 ms |
| Mimiku 待機 | Home 閒置時 | 3 格，5 fps 循環 |
| 記帳動作 | 記帳成功後播放一次 | 5 格，每格約 100 ms，播完回到 idle |
| 完成序列 | 冒險完成事件，每個事件只播一次 | 6 格，總長 ≤ 1.5 s；「跳過」鈕與 Esc 立即顯示最後一格 |
| 打字機 | 對話出現時 | 約 30–40 字／秒；打字中點擊立即補完；`aria-live` 只送一次完整句子 |
| 寶箱開關 | 點擊寶箱 | 沿用 v04 節奏 |
| 壁畫顯現 | 點擊壁畫 | 2–3 步，總長約 300 ms |
| 篝火 | 場景顯示時 | 4 格，6 fps 循環（氛圍動畫，不算主要角色動畫） |

**同時一個主要角色動畫**：主要角色動畫指 Mimiku、玩家頭像的動作與完成序列。新的主要動畫開始時，進行中的另一個立即跳到結果狀態（不排隊、不同時播放）。標題、寶箱、壁畫、篝火屬於道具或氛圍動畫，但寶箱與壁畫互動時暫停 Mimiku idle。

**減少動態（`prefers-reduced-motion` 與頁面切換）**：所有循環停在定義好的靜止格；一次性動作與完成序列直接顯示最後一格；打字機直接顯示全文；寶箱與壁畫直接切到結果狀態。狀態變化保留，只移除過程。

**不得**：持續跟隨游標、搶走焦點、延遲任何按鈕或導覽、強制使用者看完動畫才能操作、同一事件重複慶祝。

## 3. 校準審閱頁

`motion-calibration-v02-review.html`，1200×800 主要審閱視窗，另含四個 viewport 響應式檢查：

- Landing 桌機場景：標題眨眼、寶箱開關、壁畫顯現、篝火、底部對話框打字機與 CTA。
- Home 桌機／手機場景：Mimiku idle 循環、篝火；按鈕觸發「記帳成功」動作與「冒險完成」序列（含跳過）。
- 控制面板：減少動態開關、暫停全部、逐格檢視每段動畫、同時觸發兩個主要動畫以示範規則。
- 每段動畫逐格並排（實際大小與 4×），與核准 master 比較。

## 4. 驗收

- 逐格：每一格尺寸、落地點、透明 RGB、與核准 master 未改動區域的像素一致性（只允許動作部位變化，並記錄變動範圍）。
- 節奏：以 Playwright 讀取實際播放時間軸，驗證格數、每格時間、觸發條件、播放一次的動畫不重播。
- 規則：同時觸發兩個主要動畫時只有一個在播；完成序列可用按鈕與 Esc 跳過；打字機點擊補完；`aria-live` 只公告一次完整句子；動畫期間焦點不移動；所有按鈕在動畫中都能立即操作。
- 減少動態：所有動畫直接到最終狀態，循環停止，狀態仍正確。
- 頁面隱藏時循環暫停。四個 viewport 無水平溢出。
- 驗證比照既有 review：focused Vitest、ESLint、typecheck、Playwright、byte-identical 重建；產出 verification.md 與 devlog。停在 Motion 視覺審核。

## 2R. 待機節奏與完成慶祝修訂（2026-11-06）

使用者審閱 v02 後同意以下兩點修正；標題眨眼、記帳 5 格、篝火 4 格、寶箱、壁畫、打字機與所有規則測試維持不變。v02 產物唯讀，修訂另存（例如 v02r）。**不需要新的 ImageGen。**

### 修正 1 — Mimiku 待機眨眼頻率

v02 待機為「基準／微抬蓋／閉眼」三格、每格 200 ms 連續循環，等於每 0.6 秒眨一次眼。

- 待機循環只在「基準」與「微抬蓋」兩格之間交替（每格約 200–300 ms，可微調）。
- 眨眼格（idle-03）**不在循環內**，改為每 3–6 秒隨機插入一次，持續約 120–160 ms 後回到循環。
- 待機被阻擋（主要動畫、寶箱、壁畫互動）時，眨眼計時同樣暫停；減少動態時停在基準格、不眨眼；分頁隱藏時暫停。
- Playwright 以可控時鐘驗證：10 秒內眨眼 2–4 次、任兩次眨眼間隔 ≥ 3 秒、循環格只出現基準／微抬蓋。

### 修正 2 — 完成慶祝加入角色動作

v02 六格只有星光變化，角色完全不動，存在感太弱。

- 六格使用同一個**已核准的 Mimiku「開心」姿勢**（`samples/mimiku-states-actions/masters/state-happy.png`，decision-log 2026-10-02 核准 hash `1a350e5c…`），以與 Home idle 圖層**相同的 master→場景縮放倍率與落地點**取樣到桌機／手機尺寸。
- 序列（6 格，總長 ≤ 1.5 s）：落地 → 上移 2 px → 上移 3 px＋星光 → 上移 1 px＋星光 → 落地＋星光淡出 → 落地。第六格結束後，回到 Home idle 基準格。六格角色的可見寬高一致，角色只做整數像素垂直平移。
- 星光沿用 v02 的三個星光區像素；不新增金幣、文字或獎勵圖案。
- 跳過（按鈕／Esc）與減少動態時直接顯示 Home idle 基準格，並保留冒險完成結果；同一事件只播一次。
- 驗證每格尺寸、透明 RGB、角色可見寬高一致性、整數位移量與落地點。開心姿勢取樣的來源 hash 與倍率記入 manifest。
