## 3. 字標排列

桌機比較兩個版本，除了字標排列與為容納排列所必需的等比尺寸／牆面位置，場景及 live UI 相同：

### 單行版

沿用現有單行 `MIMIC` 的木製像素字形與識別細節，作為比較基準，不另選 logo 風格。

### 交錯兩行版

文字精確為上排 `MI`、下排 `MIC`，合起來仍是 `MIMIC`。

- 上排 MI 靠左；下排 MIC 向右錯開，不採兩排各自置中或左右齊邊。
- 五個字保持同一字形尺度；不得把較短的 MI 拉寬到與 MIC 等寬，也不得拉伸單一字母。
- 兩排行距略收緊，少量木製外輪廓可以交疊，表現同一整組交錯招牌；下排仍明確在上排下方。
- 重疊不得遮住識別筆畫、字標上的眼睛／愛心等辨識細節，或讓文字誤讀；不把兩排混成一行，也不增加背景牌板、繩索或新裝飾。
- 保留既有木材／黃銅／像素細節與黯淡色調。兩候選不得用不同亮度、材質、光暈或畫風來干擾排列比較。
- 按可用牆面安排整組等比尺寸，不以相同總寬強迫兩行字標放大。等大指兩行內每個字的尺度相同，不要求單行與兩行候選的實際字高完全一致；審核須列明兩者尺寸。

整組字標留在上方大片連續岩壁中，避免跨天花板、洞口、岩縫、蝙蝠與人物。可調字標本身的尺寸與位置，但不能移動人物或道具來騰位置。若無法兼顧牆面邊界與可讀性，回報具體衝突，不擅自放大牆體或改小隊落點。

使用者先前選定的 B 石壁結合／第三 C 亮度方向仍保留為後續整合事項。本輪不把交錯排列當作已完成那項精修，也不重新選招牌造型或亮度。

新交錯字標的創意 raster 稿使用 ImageGen，參照既有字標；不得以新畫 SVG、canvas 或通用文字字體代替。來源另存版本，保留實際 prompt、參照與 hash。程序只負責 deterministic 等比例整理、alpha 清理與合成，不改寫創意來源。

## 4. 手機、UI 與比較頁

- 手機以交錯兩行版為本輪比較的主要呈現，不直接裁切桌機圖。

- 登入、木牌文字、對話、CTA 與第二屏四章日誌保持 live、可讀；沿用 review-only 錨點示範，不新增認證或角色／火把等互動。

## 5. 視覺 checkpoint 與驗證

新圖必須同時呈現：

- 無法師的 A 桌機單行字標版。
- 無法師的同一 A 桌機交錯兩行字標版。
- 同一場景的手機交錯兩行版，含真實 live UI。
- 彩色、灰階、既有字標參照、來源紀錄、實際尺寸與 exact hashes。

後續實作計畫使用 TDD、focused Vitest、ESLint、型別檢查、320／390／768／1440 Playwright、determinism、透明 RGB、尺寸／alpha 遮擋及 whitespace 驗證；使用 self-review 修正重要問題，完成前以實際輸出驗證。

審核重點是：

1. 移除法師後更鬆、不失去暖火與陪伴核心。
2. 兩行字標確實上左下右、等大且輕微交疊，MIMIC 仍易讀。
3. 手機字標在完整岩壁內，桌機兩候選可直接比較。
4. 字標不壓過火與伙伴，也不遮住探索物件或 live UI。
5. 未透過移動寶箱、地圖箱或陷阱掩蓋新的構圖問題。

到此停止等待使用者對新圖的判斷。下一輪才討論寶箱、地圖木箱與陷阱位置；若需要重修小隊或背景，也須另提出具體理由。
