# Frames 家族校準

日期：2026-11-06。狀態：使用者已確認金屬色調與對話框底色；待實作。

Gate A 現況：Wordmark、Icons、Mimiku 狀態、Avatar 職業、Scenes、Props 已核准；Frames、Motion 未核准。

## 依據

- 2026-09-14 規格 §5：三層視覺階層中，Frames 屬「產品框架層」，建立 RPG 世界感但**不得遮蔽資訊**；羊皮紙用深色墨字；狀態必須有文字或圖示，不靠顏色或邊框；裝飾框不得把內容留白壓到低於舒適的觸控與閱讀空間；法律頁使用克制的石或羊皮紙框，**內文後方不得有裝飾紋理**；只有 Landing 洞窟允許水平移動，文件本身不得水平溢出。
- 校準 brief：羊皮紙、木、石、對話框、筆記本的角落、邊條、中心；邊條必須能重複組成 9-slice；中心寬敞；法律與財務閱讀面保持安靜；不含內文。拒絕：留白不足、法律／財務內文後有雜紋、用邊框傳達狀態而無文字。
- 原 Frames 樣本（`samples/frames-calibration.png`，2026-09-18）：五種框的拆法可參考，但亮金角件、深海軍藍對話框、冷灰藍石框與後來核准的暖色洞窟風格不一致，只作結構參考。

## 使用者決定（2026-11-06）

1. **金屬配件**：低調黃銅＋暗鐵，與寶箱 v04、木牌一致。亮金只留給需要強調的互動元素（例如主要 CTA 按鈕的焦點／hover），不用在框體。
2. **對話框底色**：暖深褐（審閱頁一直使用的方向，約 `#211a18`，黃銅邊約 `#b79556`），不使用深海軍藍。
   - 現有 runtime token `--mimic-color-hud-dark: #17213a`（海軍藍）與此決定不一致。Phase 1 不修改 runtime；在 decision-log 記錄，Phase 2 視覺基礎階段再更新 token。

## 1. 修訂後的 Frames 正式檔案清單

沿用 Scenes／Props 已接受的原則：**1× 邏輯像素為 master，runtime 以整數倍、`image-rendering: pixelated` 放大**。取代原計畫「256×256、32 px slice」等規定。

路徑前綴：`docs/design/assets/approved/page-visual-v1/frames/`

| 檔案 | 用途 | 中心處理 |
|---|---|---|
| `frame-parchment.png` | 法律頁、冒險檔案卡、帳本表單、記帳 | **中心不用圖**：以 CSS 純色（暖羊皮紙色）填滿 |
| `frame-wood.png` | 公會公告板、任務板、區塊標題列 | 中心可為低對比木紋 tile，但其上不放財務內文；若放內文須改用羊皮紙內襯 |
| `frame-stone.png` | 設定區塊、法律頁替代外框 | 中心 CSS 純色（暖石色） |
| `frame-dialogue.png` | Landing／Home 底部 Mimiku 對話框 | 中心 CSS 純色（暖深褐） |
| `frame-notebook.png` | 快速記帳的冒險筆記本（桌機右側抽屜、手機底部 sheet） | 中心 CSS 純色（羊皮紙），可有細裝訂線元素但不在文字區 |
| `frames.json` | 每個框的 master 尺寸、slice 寬度（邏輯 px）、建議顯示倍率、repeat 模式、中心色 token、最小內距 | — |

- 每個 master 只需容納四角＋四邊＋最小中心（例如 slice 8–12 邏輯 px、master 約 32–48 px 見方）；邊條必須可 `repeat`／`round` 無縫重複。
- slice 寬度 × 顯示倍率後的 CSS 邊框建議 16–24 px；內容內距另外保證 ≥ 16 CSS px（手機）／24 px（桌機）。
- 色彩以 Landing 道具與場景為準：暖褐木、暖羊皮紙、暖色砌石（參考 Landing 左側石砌牆，不是冷灰藍）、低調黃銅與暗鐵角件；像素顆粒與輪廓粗細與戰士 master／寶箱 v04 一致。

## 2. 校準審閱頁

做成**真的 HTML 頁面**（不是單張圖），用 CSS `border-image` 實際套用 master，以真實內容測試：

| 框 | 測試容器與內容 |
|---|---|
| parchment | 法律條文（長段落、標題、連結）；冒險檔案卡兩欄／一欄；帳務表格（右對齊、tabular numerals 金額，**僅用明顯的示範字樣**，不用看似真實的餘額） |
| wood | 公會公告板：數張任務卡（每張含文字狀態標籤）；區塊標題列 |
| stone | 設定區塊：可編輯欄位、唯讀欄位、按鈕、focus 狀態 |
| dialogue | 疊在 Landing 桌機／手機探索條與 Home 桌機／手機上：Mimiku 頭像槽、一句繁中台詞、主要 CTA 按鈕；高度符合規格（桌機約 18–22%、手機約 25–30%） |
| notebook | 桌機右側抽屜、手機底部 sheet；含表單欄位、選單、錯誤訊息、送出按鈕 |

每個框測多種尺寸：窄（280 CSS px）、中（600）、寬（1200）、矮（一行文字）、高（多段落），確認角落不被拉伸、邊條無接縫、中心安靜。

## 3. 驗收

- **對比**：羊皮紙／石框中心上的內文 ≥ 7:1，次要文字 ≥ 4.5:1；對話框上的淺色字 ≥ 7:1；CTA 文字 ≥ 4.5:1。
- **中心安靜**：放財務或法律內文的中心區域為 CSS 純色；若有任何紋理，亮度標準差需低於門檻並記錄（法律頁一律純色）。
- **9-slice 正確性**：自動檢查邊條重複接點無可見斷層（接點兩側像素欄差異不高於邊條內部平均）；角落在所有測試尺寸下為整數倍原尺寸。
- **留白**：內容與框內緣距離 ≥ 16 CSS px（手機）／24 px（桌機）；觸控目標 ≥ 44 px。
- **可存取性**：框只是裝飾，語意由 HTML landmark／heading 提供；`forced-colors` 模式下 border-image 移除後仍有可見邊框；200% 縮放與四個 viewport（320／390／768／1440）無水平溢出。
- **狀態不靠邊框**：示範的任務卡狀態以文字標籤呈現，框體不因狀態改色。
- 驗證比照既有 review：focused Vitest、ESLint、typecheck、四 viewport Playwright、byte-identical 重建；產出 verification.md 與 devlog。停在 Frames 視覺審核。

## 範圍

只做 Phase 1 review；不修改 web/public、runtime、tokens.css、registry、PWA、service worker、產品頁或帳務；不標示 approved；不做 production exports／Phase 2。不使用 worktree／subagent，不 stage／commit；既有核准產物唯讀；devlog 只追加。可順便把 `review-manifest.json` 中 scenes／props 的樣本更新為 decision-log 已核准者並跑其 contract；若會牽動既有測試則分開回報，不要強行修改。

## 2R. 原圖重繪（2026-11-06）

使用者審閱第一版後選擇方案 A：**保留整套 9-slice 框架、審閱頁與測試，只重畫五張原圖**。

### 審閱發現

- 功能面完整：對比（羊皮紙內文 12.44:1、對話框 13.66:1 等）、30 種尺寸角件不變形、邊條接點差異 0、中心純色、留白、44 px 觸控、焦點、forced-colors、200% 縮放皆通過。
- 美術面單薄：五張 36×36 原圖由合成器程式繪製（`drawFrame`），未使用 ImageGen。木框只有虛線、石框是灰色帶狀、黃銅暗鐵配件只剩角落一個小方點；與已核准的洞窟場景、寶箱、人物並列時落差明顯，像上色的 CSS 邊框。

### 重繪要求

- **以 ImageGen 繪製**五張原圖的來源（可一張多格圖再拆分），保存所有嘗試、prompt、lineage；以寶箱 v04、木牌、地圖木箱、Landing 石砌牆為風格與材質參照，像素顆粒與輪廓粗細與戰士 master 一致。
- 切片放寬至 **12–16 邏輯 px**（顯示 2× → 24–32 CSS px），原圖約 44–56 px 見方，留出角件造型空間；`frames.json` 更新 slice、尺寸與最小內距（內容內距仍 ≥ 16／24 CSS px，若邊框加寬則內距相應增加）。
- 各框材質：
  - **羊皮紙**：微捲、略有磨損的紙緣，角落小型低調黃銅護角；中心 CSS 純色不變。
  - **木**：看得出 1–2 條木板與木紋的邊條，角落暗鐵包角加鉚釘（呼應寶箱 v04 的鐵箍）。
  - **石**：暖色砌石（參考 Landing 左側石牆的色調與石塊大小），邊條是一排可重複的石塊，角落較大的角石；不是冷灰。
  - **對話框**：暖深褐底，黃銅細邊條，角落有造型的黃銅角飾（克制，不華麗、不發光），可有一個極小的鉚釘節奏。
  - **筆記本**：皮革封面邊緣與縫線，可在一側有裝訂帶或皮扣（僅在角件或邊條內，不進入文字區），內頁中心 CSS 純色。
- 邊條必須仍可 `repeat` 無縫重複（ImageGen 產出後如需，可用確定性方式取一段可重複單元並記錄）；角件不可被拉伸。
- 不得加入文字、符號、金額、狀態色；亮金只保留給 CTA 互動狀態，不用在框體。

### 驗收

- 沿用第一版全部 contract（對比、留白、邊條接點、角件不變形、forced-colors、200%、四 viewport、無水平溢出），並以新原圖重跑。
- 審閱頁加入第一版與 2R 並排比較（同一尺寸、同一場景）。
- 驗證、verification.md、devlog 後停在視覺審核。
